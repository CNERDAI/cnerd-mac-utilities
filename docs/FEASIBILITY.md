# CNERD Mac Utilities 1.0: Feasibility and Decisions

Last updated: 2026-11-14 (version 1.2.0)

This file records what macOS allows, what Version 1.0 does about it, and why. Update it when a decision changes.

## Environment and targets

| Item | Value |
| --- | --- |
| Built and checked on | macOS 27.2.1, Xcode 27.2, Swift 6.4, Apple silicon |
| Deployment target | macOS 14.0 |
| Language mode | Swift 6 (strict concurrency) |

Why macOS 14: it is the oldest release with everything used here (the Observation framework, `SMAppService`, the current System Settings layout) and it still covers Macs several years old.

## Distribution decisions

- **Free and open source.** MIT license. No trial, no serial number, no account. Development is supported by optional donations through the CNERD shop.
- **Nothing is locked behind a donation.** The CNERD AI name and the app logo always show. A lock in an open source app can be removed by anyone who builds it, so it would only get in the way of honest users.
- **Names and logos are not part of the MIT license.** The license covers the source code. See `TRADEMARKS.md` for the CNERD AI names and logos, and for the names and logos that belong to others.
- **No App Sandbox.** The Accessibility API cannot control other apps' windows from a sandboxed app. This rules out the Mac App Store. Downloads are signed with a Developer ID certificate and notarized by Apple.
- **Hardened Runtime is on.** One entitlement is used: `com.apple.security.automation.apple-events` (needed to ask Finder for its selection, to have Finder empty the Trash, and to change Dock settings through System Events).
- **Signing for local builds.** The default is ad-hoc signing, which needs no developer account. With ad-hoc signing, macOS drops the Accessibility permission after every rebuild. A private `Config/Signing.local.xcconfig` with a real Apple Development certificate avoids that.

#### Green button: what is and is not possible

There is **no public API** to change what another app's green button does. The button belongs to each app's own window.

What public APIs do allow:

1. A `CGEventTap` can see mouse clicks before apps do. It needs the Accessibility permission.
2. The Accessibility API can report what is under the pointer. A standard green button reports the subrole `AXFullScreenButton` or `AXZoomButton`.
3. So the app can hold back a click that lands on a standard green button and maximize the window itself.

This is a workaround built on public APIs, not a supported way to redefine the button. Known limits:

- Apps that draw their own window buttons, or do not expose them to Accessibility, are not affected. They keep macOS behavior.
- Option-click, and any click with a modifier key, is passed through untouched.
- Windows already in Full Screen are passed through so the button can still exit Full Screen.
- The menu that appears when the pointer rests on the green button still works. Only the click is replaced.
- Full Screen stays available from the View menu or Control-Command-F.
- If macOS ever finds the tap slow it disables it. The app turns it back on.
- Every left click runs a quick window-list check while this is on. The Accessibility query only runs for clicks near the top of a window.
- If a click cannot be identified for certain, it goes to macOS unchanged.

Rejected approaches: code injection into other apps, private window server APIs, and anything that needs System Integrity Protection off.

Note: macOS 15 and later also include built-in window tiling (drag to an edge, Globe key shortcuts). The Window Manager adds the Windows-style restore toggle, the green button behavior, and one set of shortcuts across macOS 14 and later.

## Behavior rules that apply everywhere

- The app never asks for a permission on its own. A request only happens when the user clicks a button or first uses the feature that needs it.
- When a module is off, it does nothing: no hot keys, no click watching, no taskbar windows. It only keeps lightweight listeners for app and display changes.
- No polling, with one bounded exception: after the user clicks a button to grant Accessibility, the app checks every two seconds for up to five minutes, then stops.
- No network use, no telemetry, no account.
- No file on the Desktop is ever moved, renamed, or deleted.
