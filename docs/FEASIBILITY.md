# CNERD Mac Utilities 1.0: Feasibility and Decisions

Last updated: 2026-11-12

This file records what macOS allows, what Version 1.0 does about it, and why. Update it when a decision changes.

## Environment and targets

| Item | Value |
| --- | --- |
| Built and checked on | macOS 27.2.1, Xcode 27.2, Swift 6.4, Apple silicon |
| Deployment target | macOS 14.0 |
| Language mode | Swift 6 (strict concurrency) |
| UI | SwiftUI, with AppKit for system work |
| Dependencies | None |
| Project file | Generated by XcodeGen from `project.yml` |
| Bundle ID | `ai.cnerd.MacUtilities` |

Why macOS 14: it is the oldest release with everything used here (the Observation framework, `SMAppService`, the current System Settings layout) and it still covers Macs several years old.

## Distribution decisions

- **Free and open source.** MIT license. No trial, no serial number, no account. Development is supported by optional donations through the CNERD shop.
- **No App Sandbox.** The Accessibility API cannot control other apps' windows from a sandboxed app. This rules out the Mac App Store. Downloads are signed with a Developer ID certificate and notarized by Apple.
- **Hardened Runtime is on.** One entitlement is used: `com.apple.security.automation.apple-events` (needed to ask Finder for its selection and to change Dock settings through System Events).
- **Signing for local builds.** The default is ad-hoc signing, which needs no developer account. With ad-hoc signing, macOS drops the Accessibility permission after every rebuild. A private `Config/Signing.local.xcconfig` with a real Apple Development certificate avoids that.

## Feature by feature

Status meanings: **Built** = implemented with public APIs. **Beta** = implemented with public APIs, with known gaps. **Not built** = left out on purpose.

### Module 001: Window Manager

| Feature | Status | How | Limits |
| --- | --- | --- | --- |
| Maximize and restore | Built | Accessibility API (`AXUIElement`): read the window frame, set it to the display's usable area, remember the old frame in memory | Needs the Accessibility permission. Some apps refuse or adjust the size (minimum sizes, fixed-size windows). Restore memory is lost when the app quits. |
| Left half, right half, center | Built | Same API | Same as above |
| Multiple displays | Built | The window's display is the one showing most of it. Uses `NSScreen.visibleFrame`, so the menu bar and Dock are respected. | None known |
| Global keyboard shortcuts | Built | Carbon `RegisterEventHotKey`, still the supported public API for global hot keys. No extra permission. | Defaults are Control-Option with arrows and C. VoiceOver also uses Control-Option, so VoiceOver users should change them. |
| Shortcut conflict check | Built | `CopySymbolicHotKeys` lists the shortcuts macOS has enabled. Those are refused. | Cannot see shortcuts owned by other third-party apps. If registration fails the row shows a warning. |
| Green button click | Beta, off by default | See below | See below |

#### Green button: what is and is not possible

There is **no public API** to change what another app's green button does. The button belongs to each app's own window.

What public APIs do allow:

1. A `CGEventTap` can see mouse clicks before apps do. It needs the Accessibility permission.
2. The Accessibility API can report what is under the pointer. A standard green button reports the subrole `AXFullScreenButton` or `AXZoomButton`.
3. So the app can hold back a click that lands on a standard green button and maximize the window itself.

This is a workaround built on public APIs, not a supported way to redefine the button. Known limits:

- Apps that draw their own window buttons, or do not expose them to Accessibility, are not affected. They keep macOS behavior.
- Option-click, and any click with a modifier key, is passed through untouched.
- Windows already in Full Screen are passed through so the button can still exit Full Screen.
- The menu that appears when the pointer rests on the green button still works. Only the click is replaced.
- Full Screen stays available from the View menu or Control-Command-F.
- If macOS ever finds the tap slow it disables it. The app turns it back on.
- Every left click runs a quick window-list check while this is on. The Accessibility query only runs for clicks near the top of a window.
- If a click cannot be identified for certain, it goes to macOS unchanged.

Rejected approaches: code injection into other apps, private window server APIs, and anything that needs System Integrity Protection off.

Note: macOS 15 and later also include built-in window tiling (drag to an edge, Globe key shortcuts). The Window Manager adds the Windows-style restore toggle, the green button behavior, and one set of shortcuts across macOS 14 and later.

### Module 002: Finder Enhancements

| Feature | Status | How | Limits |
| --- | --- | --- | --- |
| Show hidden files | Built | Reads and writes Finder's `AppleShowAllFiles` preference, then asks Finder to quit and reopens it | The key is not formally documented by Apple. | Other Finder preferences (path bar, status bar, extensions) | Not built | These are also undocumented preference keys | Add only after review, one at a time |

### Module 004: Taskbar & Dock

Background: macOS shows one Dock, on one display at a time. There is no public API or setting that shows it on all displays at once, and none that pins it to a chosen display. So the module has two parts: our own taskbar, and switches for the real Dock.

| Feature | Status | How | Limits |
| --- | --- | --- | --- |
| Taskbar on chosen displays | Built, off by default | One borderless floating `NSPanel` per display, placed inside `NSScreen.visibleFrame`. Choices: all displays, main display only, other displays only. | Sits beside the Dock when both use the same edge of the same display. Hidden in Full Screen. |
| Taskbar position: bottom, top, left, right | Built | The panel is placed on the chosen edge of the usable area. Independent of the Dock's position. | One position for all displays. A different position per display is not built. |
| Icon size, app names on or off, name left, right, above, or below the icon | Built | The bar's thickness is worked out from these settings (`TaskbarLayout`), and the view uses the same numbers | A side bar with names beside the icons is wide (about 180 points) |
| Glass background on or off | Built | `NSVisualEffectView` when on, solid window color when off | Uses the standard translucent material, which works back to macOS 14. It is not the newer Liquid Glass API. |
| Square or rounded edges | Built | Rounded pulls the panel 6 points in from the screen edge and rounds the corners. The glass is cut to shape with a mask image. | The bar still runs the full length of the edge. It does not shrink to fit its apps the way the Dock does. |
| App name size | Built | Four sizes, 9 to 14 points. The bar's thickness and name width scale with it. | None known |
| Running apps on the taskbar | Built | `NSWorkspace.runningApplications`, updated from workspace notifications (launch, quit, activate, hide). No polling. | Shows apps, not individual windows. Every taskbar shows the same list. |
| Keep in Taskbar, Remove from Taskbar | Built | Kept apps are stored by bundle identifier and shown even when not running. Clicking one launches it. | Apps without a bundle identifier cannot be kept |
| Drag to reorder, order is saved | Built | SwiftUI drag and drop. The dragged app goes before or after the app under the pointer, depending on which half the pointer is over. The order is stored by bundle identifier, so every app returns to its spot. | None known |
| Click to switch, click the front app to hide | Built | `NSWorkspace.openApplication`, `NSRunningApplication.hide` | None known |
| Right-click menu: Show All Windows, Hide, Keep in Taskbar, Show in Finder, Quit | Built | `NSRunningApplication` and `NSWorkspace` | Quit is a normal quit request, so the app can still ask to save. Open at Login for other apps is not possible: Apple only lets an app register itself. |
| Show All Windows | Built, not yet run | Brings all the app's windows forward (`activateAllWindows`), then starts Mission Control with the argument `2`, which shows the front app's windows | That argument is not documented by Apple. If it stops working, the windows are still brought forward. |
| Trash on the taskbar | Built | Opens the Trash folder in Finder | Does not show full or empty, cannot empty the Trash, and files cannot be dropped on it yet |
| Taskbar follows the Dock | Built | When the Dock is hidden, the taskbar uses the Dock's strip of the screen and slides there. Dock changes made anywhere are picked up from the Dock's `com.apple.dock.prefchanged` notification. | On macOS 27, `NSScreen.visibleFrame` was measured to keep the Dock's strip reserved while the Dock is hidden, so the app works out the free area itself (`NSScreen.usableFrame`). The notification name is not documented by Apple. Without it the taskbar re-seats on the next app or display change. |
| Turn off the macOS Dock | Built, not yet run | Sets the Dock to auto-hide and writes `autohide-delay` = 1000 to the Dock's preferences so it never slides back in, then restarts the Dock (`killall Dock`). Turning it off removes the value and restores the earlier auto-hide setting. | **No supported API exists for this.** `autohide-delay` is an undocumented Dock preference and could stop working in a future macOS. The app asks before doing it. Minimized windows and the Dock's own Trash are out of reach while the Dock is off. |
| Keep windows clear of the taskbar | Built | Window Manager subtracts the taskbar from the usable area on whichever edge it sits | **Only this app's maximize and snap know about the taskbar.** macOS lets only the Dock reserve screen space, so windows sized by hand, by macOS tiling, or by other tools can sit behind it. |
| Dock auto-hide, position, size | Built | Written through System Events `dock preferences`, Apple's scripting interface. Current values are read from the Dock's preferences so no prompt is needed just to look. | macOS asks once for Automation permission for System Events. The read uses the Dock's preference keys (`autohide`, `orientation`, `tilesize`), which are not formally documented. |
| Dock on all displays, or pinned to one display | Not possible | No public API | The taskbar is the substitute |

## Behavior rules that apply everywhere

- The app never asks for a permission on its own. A request only happens when the user clicks a button or first uses the feature that needs it.
- When a module is off, it does nothing: no hot keys, no click watching, no taskbar windows. It only keeps lightweight listeners for app and display changes.
- No polling, with one bounded exception: after the user clicks a button to grant Accessibility, the app checks every two seconds for up to five minutes, then stops.
- No network use, no telemetry, no account.
- No file on the Desktop is ever moved, renamed, or deleted.

## Known gaps in this build

- Taskbar, checked on three displays: bottom, top, and left edges, names off, below, and left of the icons, glass on and off, rounded edges, the Trash, drag to reorder in both directions, and sliding when the Dock's auto-hide changes.
- Taskbar, not yet run: Turn Off the macOS Dock, Show All Windows, Keep in Taskbar, and the click, hide, and quit actions.
- The main window opens at every launch, including launch at login.
- Restore positions are kept in memory only.
- Not yet checked on macOS 14, 15, or 26, or on an Intel Mac.

## Manual test checklist

Unit tests cover geometry, taskbar layout and ordering, shortcuts, sorting, settings storage, and symbol names. These need a person:

- [ ] Accessibility denied: window buttons are disabled and the permission notice shows
- [ ] Accessibility granted: maximize, restore, left, right, center in Safari, Finder, Terminal, and one Electron app
- [ ] Restore returns the window to its exact earlier size and position
- [ ] Two displays: each action stays on the window's own display
- [ ] Dock on the left, right, and hidden: maximize respects the usable area
- [ ] A window in Full Screen is left alone and a message shows
- [ ] Green button beta: click maximizes, click again restores, Option-click still zooms
- [ ] Record a new shortcut, quit, reopen: the shortcut is still there
- [ ] Recording a macOS shortcut (for example Command-Space) is refused
- [ ] Show Hidden Files: Finder restarts and the switch matches Finder after reopening the app
- [ ] Copy Path with one item, several items, and nothing selected
- [ ] Desktop access denied: a clear message shows
- [ ] Taskbar: each Show On choice with two or more displays, unplug and replug a display
- [ ] Taskbar: each position, edge style, icon size, name position, and name size. Quit and reopen with the taskbar on
- [ ] Taskbar: click an app, click the front app, drag to reorder, quit and reopen, the order is the same
- [ ] Taskbar: Keep in Taskbar, quit that app, it stays and reopens with a click. Remove from Taskbar
- [ ] Taskbar: Show All Windows, Show in Finder, Hide, Quit, Trash
- [ ] Taskbar on, then maximize: the window stops at the edge of the taskbar
- [ ] Dock switches: auto-hide, each position, size. The taskbar slides into or out of the Dock's space
- [ ] Turn Off the macOS Dock, then turn it back on. Auto-hide returns to what it was
- [ ] Donate menu: each amount opens the shop with that amount
- [ ] Launch at Login on, log out, log in
- [ ] Each module off: its controls are disabled and nothing reacts
- [ ] Light and dark appearance
- [ ] Idle CPU near zero in Activity Monitor
